## 2. プロジェクト概要

### 2.1 目的
お客様（一般生活者）向け対話型チャットLLMアプリケーション基盤の開発

### 2.2 背景
食品関連の問い合わせ対応を効率化し、ユーザーに対してパーソナライズされたレシピ提案や製品情報を提供することで、顧客体験を向上させる。

### 2.3 対象ユースケース

| ユースケース | 説明 | 優先度 |
|------------|------|--------|
| ほんだし | 和食・だし関連の相談・レシピ提案・製品FAQ | MVP対象 |
| たんぱく質関連製品 | 健康・栄養相談、運動提案 | Phase 2以降 |
| 料理初心者支援 | 基礎的な料理相談・レシピ提案 | Phase 2以降 |

#### 3.2.1 性能要件（NFR-001）

| 要件ID | 要件名 | 目標値 | 測定方法 | MVP対象 |
|--------|--------|--------|----------|---------|
| NFR-001-01 | 応答時間 | 平均3秒以内、P95 5秒以内 | Application Insights | ✅ |
| NFR-001-02 | スループット | 60リクエスト/分（レート制限値） | 手動確認 | ✅ |
| NFR-001-03 | 同時接続数 | 100ユーザー | - | ❌ Phase 2 |
| NFR-001-04 | 可用性 | 99%以上（月間、計画メンテナンス除く） | Application Insights | ✅ |
| NFR-001-05 | セッションタイムアウト | 無操作30分 | アプリケーション | ✅ |
| NFR-001-06 | 最大会話長 | 1会話100メッセージ、コンテキスト8000トークン | アプリケーション | ✅ |

> **MVPでの性能確認**
> - **負荷テストは実施しません**: 大規模な同時アクセスは想定していないため
> - **手動確認のみ**: ブラウザ開発者ツールで応答時間を確認（5秒以内）
> - **レート制限動作確認**: 60 req/min超過時に429エラーが返ることを確認
> - **Phase 2以降**: 利用状況に応じて負荷テスト（k6）を検討

> **可用性99%の計算**
> - 月間ダウンタイム許容: 約7.2時間
> - **計画メンテナンス除外**: 事前告知（24時間前）のメンテナンスはSLA計算から除外

> **コンテキスト8000トークン制限の根拠**
> - GPT-4oは128Kトークン対応だが、コスト最適化のため8000トークンに制限
> - 8000トークン ≒ 日本語約4000文字（十分な会話履歴を保持可能）
> - **MVP版**: 超過時は古いメッセージから単純削除（最新10メッセージを保持）
> - **Phase 2以降**: LLMによる会話要約で圧縮（コンテキスト品質維持）

**SLO監視・アラート対応フロー**
1. Application Insightsでメトリクス監視
2. アラート条件到達時にSlack/Teams通知
3. 運用担当者が状況確認・対応判断
4. 必要に応じてスケールアウト or 障害対応

### 3.2.1a 意図分類（Intent Detection）

ユーザーメッセージから意図を分類し、適切な応答・データ取得を行う。

**分類方式**: LLMベース（GPT-4oによる分類）

| intent | 説明 | トリガー例 | 後続処理 |
|--------|------|-----------|---------|
| `recipe_search` | レシピを探している | 「味噌汁の作り方」「簡単な煮物」 | RAGでレシピ検索 |
| `recipe_provided` | レシピ提供後の会話 | （レシピ表示後の質問） | 追加情報提供 |
| `product_info` | 製品情報を知りたい | 「ほんだしの種類」「サイズは？」 | 製品データ検索 |
| `faq_question` | よくある質問 | 「保存方法」「アレルギー」 | FAQ検索 |
| `faq_answered` | FAQ回答後の会話 | （FAQ表示後の質問） | 追加情報提供 |
| `general_chat` | 一般的な会話 | 「ありがとう」「こんにちは」 | LLM直接応答 |
| `out_of_scope` | 対応範囲外 | 「天気を教えて」「株価は？」 | 範囲外応答 |

**分類プロンプト（概要）**
```
ユーザーの質問を以下のカテゴリに分類してください：
- recipe_search: レシピを探している
- product_info: 製品情報を知りたい
- faq_question: 保存方法・アレルギー等のFAQ
- general_chat: 挨拶・お礼等
- out_of_scope: ほんだし・料理と無関係

質問: {user_message}
カテゴリ:
```

**分類フォールバック**

| 条件 | フォールバック先 | 理由 |
|------|----------------|------|
| LLM分類タイムアウト（3秒） | `general_chat` | ユーザー体験優先 |
| LLM分類エラー | `general_chat` | 安全なデフォルト |
| 分類結果が不明瞭 | `general_chat` | LLM直接応答で対応 |
| 複数intentが競合 | 信頼度最高のintent | 確率スコアで判定 |

> **精度目標**: 分類精度90%以上（LLM品質テストで検証）

**MVPアクセス制限（パスワード認証）**

MVP期間中は、特定のパスワードを知っている人だけがアプリケーションにアクセスできるようにします。

| 項目 | 設定 |
|------|------|
| 認証方式 | シンプルパスワード認証（フロントエンド） |
| パスワード保存 | 環境変数（`MVP_ACCESS_PASSWORD`） |
| セッション保持 | sessionStorage（ブラウザタブ単位） |
| 有効期限 | ブラウザタブを閉じるまで |
| 試行回数制限 | 5回/分（ブルートフォース対策） |

**認証フロー**

```
┌─────────────────┐     パスワード入力      ┌─────────────────┐
│  パスワード      │ ──────────────────────→ │  バックエンド    │
│  入力画面       │                         │  検証API        │
└─────────────────┘                         └─────────────────┘
        │                                           │
        │ 認証失敗                                   │ 認証成功
        ↓                                           ↓
┌─────────────────┐                         ┌─────────────────┐
│  エラー表示      │                         │  sessionStorage │
│  (残り試行回数)  │                         │  にトークン保存  │
└─────────────────┘                         └─────────────────┘
                                                    │
                                                    ↓
                                            ┌─────────────────┐
                                            │  チャット画面    │
                                            │  へリダイレクト  │
                                            └─────────────────┘
```

**実装仕様**

| コンポーネント | 実装内容 |
|--------------|---------|
| フロントエンド | パスワード入力画面、sessionStorageチェック |
| バックエンドAPI | `POST /api/v1/auth/verify` パスワード検証エンドポイント |
| 環境変数 | `MVP_ACCESS_PASSWORD`: アクセスパスワード（ハッシュ化して保存） |

**パスワード入力画面の仕様**

| 項目 | 仕様 |
|------|------|
| 表示条件 | sessionStorageに有効なトークンがない場合 |
| 入力フィールド | パスワード（マスク表示） |
| ボタン | 「アクセスする」 |
| エラー表示 | 「パスワードが正しくありません（残り○回）」 |
| ロックアウト | 5回失敗で1分間ロック |

> **注記**: 
> - これはMVP期間の**限定公開用**の簡易認証です
> - 本格的なユーザー認証（Azure AD B2C等）はPhase 3で実装予定
> - パスワードは関係者のみに共有し、定期的に変更してください

**レート制限の実装方式（MVP）**

| 方式 | 概要 | メリット | デメリット | 推奨度 |
|------|------|---------|-----------|--------|
| **Azure API Management (Consumption)** | APIM Consumptionプランで制限 | 設定のみで実装可、正確 | 追加コスト（従量課金） | ⭐⭐⭐ **採用** |

> **採用方針**: Azure API Management (Consumption層) をMVPから導入。
> - Container Apps + APIM の構成でレート制限を正確に実装
> - Consumptionプランは従量課金（約¥1,500〜3,000/月）で初期コストを抑制
> - 将来のDeveloperプランへの移行もスムーズ

**MVP構成**
```
クライアント → APIM (レート制限・認証) → Container Apps (FastAPI) → Azure OpenAI
```

```

【応答形式】
- レシピ提案時は材料と手順を構造化
```

**実装方針**
```javascript
// セッションID取得/生成
function getOrCreateSessionId() {
  let sessionId = localStorage.getItem('foodllm_session_id');
  if (!sessionId) {
    sessionId = sessionStorage.getItem('foodllm_session_id');
  }
  if (!sessionId) {
    sessionId = crypto.randomUUID();
    try {
      localStorage.setItem('foodllm_session_id', sessionId);
    } catch (e) {
      sessionStorage.setItem('foodllm_session_id', sessionId);
    }
  }
  return sessionId;
}
```
